At the moment we do not have any persistent memory to hold what user types. So if the pc shutsdown in-between user typing or the page is refreshed then the user will lost the data he/she typed. To handle this, i think we can create a temporary session to hold the data for 1.5 hours from creating time. We will save the session every 10 sec (or whichever time you think won't harm my cpu) to hold on the latest data. We will give an option to user to name the session partially, and the session name will be finished with latest date format ddmmyyyy. For example, "whatever-user-named-ddmmyyyy", "Naim-08032026". We will ofcourse give user another option to recover data by session name, but instead of typing the whole name user will only type the same name provided earlier, and the script will use the same date format to find and fetch data from the session, if available. The session method will be only applicable in the "Manual Input" tab. If no session name is provided by the user then the script will generate a default name for the session. As mentioned the sessions will exist for 1.5 hour and then will be deleted. All of it are for the web-ui only.
